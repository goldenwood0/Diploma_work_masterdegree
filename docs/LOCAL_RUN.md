## Запустить

Docker Desktop должен быть доступен. Если существующий `zhpath-db-1` остановлен:

```powershell
docker compose start db
docker inspect zhpath-db-1 --format '{{.State.Status}} {{.State.Health.Status}}'
```

Дождитесь `running healthy`. Если контейнера или volume нет, остановитесь:
создание новой пустой БД не восстанавливает имеющиеся данные. Не выполнять
`docker compose up` без имени сервиса, `down -v`, db:deploy, db:migrate, db:seed,
db:generate или копирование `.env.example` поверх `.env`.

Сборка API (установленные зависимости уже доступны):

```powershell
npm run server:build
```

В отдельном терминале, если 3001 свободен:

```powershell
Set-Location 'C:\Users\Sultan\Desktop\Diplom'
npm run server:dev
```

Эта команда выполняет `node --env-file=.env dist-server/main.js`. Дождитесь
`ZhPath API listening on port 3001`. API не пересобирается автоматически.

Для настоящего ИИ на этом Windows-окружении подтверждена необходимость доверия
системным CA: обычный Node получил `SELF_SIGNED_CERT_IN_CHAIN`. После устранения
ограничения баланса запускайте API так (это штатная опция Node, проверка TLS
остаётся включённой; npm scripts и `.env` не менялись):

```powershell
node --use-system-ca --env-file=.env dist-server/main.js
```

Бесплатный GET модели с этой опцией прошёл, но успешная генерация ещё не получена.
История и дальнейшая проверка: [ai-acceptance/README.md](ai-acceptance/README.md).

Если Vite на 8443 ещё не работает, в другом терминале:

```powershell
Set-Location 'C:\Users\Sultan\Desktop\Diplom'
npm run dev -- --host 127.0.0.1
```

Открыть [приложение](http://127.0.0.1:8443). Используйте `127.0.0.1`, а не
`localhost`: OriginGuard ожидает точное совпадение APP_ORIGIN. Vite проксирует
`/api` на 3001. Не нажимайте отправку ИИ, регистрацию или восстановление пароля.

## Проверить

Health подтверждает процесс API, но сам по себе не проверяет БД. Скрипт ниже
проверяет окружение, подключение к выбранной БД, прямой health и прокси Vite.
Без аргументов он не создаёт данных:

```powershell
node --env-file=.env scripts/check-local-session.mjs
```

Отдельная проверка сессии создаёт только собственного временного STUDENT
на адресе `example.invalid`, с подтверждением email напрямую в БД и выключенными
напоминаниями. Пароль случайный, хранится только в памяти и не выводится.
Существующие пользователи/роли/уроки/прогресс не изменяются:

```powershell
node --env-file=.env scripts/check-local-session.mjs --session
```

Ожидаются PASS для БД, обоих health, входа, cookie HttpOnly/SameSite=Strict,
сессии именно в выбранной БД, `/auth/me`, выхода, отказа отозванной cookie и
очистки. При провале — ненулевой exit code. Скрипт не вызывает регистрацию,
почтовые маршруты или tutor. Проверка HTTP через Vite не является браузерной
приёмкой интерфейса или методической оценкой.

Временный аккаунт, настройки и сессии удаляются в finally. Если процесс был
принудительно прерван, используйте **точный** напечатанный Fixture-маркер:

```powershell
node --env-file=.env scripts/check-local-session.mjs --cleanup=local-start-<uuid>
```

Замените `<uuid>` фактическим значением, не запускайте строку с placeholder.
Очистка проверяет маркеры id/email/name и роль, не требует работающего API/Vite
и допускает повторный вызов. Не удаляйте чужие fixtures или все тестовые записи.
