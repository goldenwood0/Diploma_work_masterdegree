# Архитектура на старте

Спринт 5: `ReviewCard`, `ReviewEvent`, API `/api/reviews`, импорт изученных слов,
расписание и самопроверка на экране Reviews. [Контракт и ограничения](SPRINT_5.md).

Спринт 4: `Quiz` и `QuizAttempt`, серверный модуль проверки `server/quiz.ts`,
форма `QuizPanel` с шестью типами заданий. Урок с тестом завершается только при

Спринт 3: каталог и блоки уроков в PostgreSQL, `LearningController`, прогресс
по пользователю/уроку, проверка зависимостей и версии содержания. API:
`GET /api/learning/catalog`, `GET /api/learning/lessons/:slug`,
`PUT /api/learning/lessons/:slug/progress`. Тело сохранения: `{ blockId, revision }`.
Клиент валидирует ответы в `src/api/learning.ts`; маршруты уроков динамические.
Начальные данные: `server/seed.ts`, `pnpm db:seed`. Главная и каталог используют
одни и те же данные. [Контракт и ограничения](SPRINT_3.md).

Спринт 2: подключены профиль, онбординг и локализация; контракт аккаунта теперь
содержит настройки, а профиль сохраняется через PATCH /api/profile.
Подробности: [SPRINT_2.md](SPRINT_2.md).

Актуализация после спринта 1: сервер NestJS, PostgreSQL и Prisma подключены,
клиент авторизации использует `/api`, Vite proxy настроен. Аккаунты и сессии
реальные; учебные данные пока демонстрационные. Ниже сохранено описание исходного
спринта 0. Текущий контракт, запуск и ограничения: [SPRINT_1.md](SPRINT_1.md).

## Реализовано в спринте 0

- `src/App.tsx`: композиция экранов и оболочка навигации.
- `src/pages`: главная, каталог, урок, профиль, заглушка повторения и 404.
- `src/components`: кнопки навигации, карточка слова, панель ИИ, ErrorBoundary.
- `src/app`: карта маршрутов и подписка на смену hash.
- `src/api/client.ts`: общий запрос JSON, HTTP/сетевые ошибки, отмена через signal.

Адреса: `#/`, `#/courses`, `#/lessons/hsk1-greetings`, `#/profile`, `#/reviews`.
Hash выбран для работы в Figma и статическом размещении без правил перенаправления.
Неизвестный hash показывает 404. При добавлении динамических уроков в спринте 3
маршруты нужно расширить идентификаторами из каталога.

Данные остаются демонстрационными. API-клиент ещё не вызывается экранами,
реальных серверных endpoint нет. ErrorBoundary обрабатывает ошибки рендеринга;
ошибки запросов должны отображаться состояниями конкретного экрана при подключении API.

## Рабочий выбор для следующих спринтов

Сохраняем React + Vite + Tailwind. Сервер — модульный монолит NestJS/TypeScript,
PostgreSQL и Prisma. Это план, зависимости сервера пока не установлены.
Сначала auth/users, далее catalog/learning, assessments/reviews, content-admin,
media, analytics и ai-tutor. Внешние сервисы подключаем по мере появления задач.

В production `/api` направляется на сервер; локальный proxy будет настроен
после появления сервера. Сессии — cookie HttpOnly с серверной проверкой и CSRF-защитой
для изменяющих запросов. Подробный контракт авторизации определяется в спринте 1.
Доменный модуль валидирует неизвестный JSON из API-клиента перед использованием.
Секреты БД, почты и ИИ не должны попадать в клиентские `VITE_*` переменные.

## Проверка

`pnpm install --frozen-lockfile`, затем `pnpm typecheck` и `pnpm build`.
В браузере: открыть каждый адрес напрямую, обновить страницу, проверить
переходы и Назад/Вперёд, неизвестный адрес и мобильную навигацию.
Сервер Vite в среде Figma запускается платформой.

В локальной копии 09.09.2026 запущенного сервера не было; для проверки запущен
Vite на 127.0.0.1:8443. Исходный lucide-react 1.43.0 был отклонён политикой
минимального возраста пакетов. Закреплена версия 1.42.0, lockfile пересоздан
с версиями в разрешённых диапазонах package.json; повторная frozen-установка успешна.
Исходный oxfmt 0.2.0 не предоставил доступную команду в этой Windows-среде;
автоформатирование не выполнено. TypeScript и Vite проходят проверки.
