## Реализовано

- Экран `/#/content` для EDITOR/ADMIN: список уроков, создание черновика в
  существующем разделе, названия ru/kk/en и длительность.
- Новый урок добавляется в конец раздела. Предыдущий урок этого раздела становится
  обязательным условием доступа; пока он не опубликован и не пройден, новый урок
  будет закрыт ученику. Адрес урока уникален, после создания не изменяется.
- Визуальные формы словарных, текстовых и аудиоблоков: добавление, удаление,
  перестановка, слова, пиньинь, переводы ru/kk/en, автор/лицензия/HTTPS-ссылки.
  Максимум 40 блоков и 100 слов на словарный блок. Пустой черновик допустим.
- Черновик → проверка → публикация → архив → черновик. Публикация и архив
  требуют ADMIN; STUDENT не получает доступ к редакторскому API.
- Сервер проверяет типы блоков, обязательные переводы и HTTPS-ссылки при
  сохранении содержания и публикации. Урок без блоков опубликовать нельзя.
- Опубликованные уроки защищены от редактирования. Архив скрывает урок от
  учеников; независимого черновика поверх опубликованной версии пока нет.
- Предпросмотр текущей формы, включая аудиоплеер и атрибуцию.
- Предупреждение о несохранённых изменениях при смене урока, обновлении формы,
  переходах приложения и закрытии/перезагрузке страницы. До сохранения кнопки
  изменения статуса заблокированы.
- editVersion защищает от устаревших записей. Транзакция сохраняет содержание
  и журнал с actorId, временем и снимками до/после. Новые записи журнала включают
  блоки, старые записи первого этапа содержат только метаданные.
- Изменение содержания/порядка блоков увеличивает учебную revision: старый
  прогресс не засчитывается для новой версии. Сохранение идентичных блоков или
  только названия/длительности не сбрасывает прогресс. Старые попытки тестов
  остаются со своими снимками заданий и результатов.

## Редактор заданий

- Создание теста урока или модуля, порог прохождения от 1 до 100 процентов.
- Шесть форм: выбор ответа, пары, порядок слов, пропуск, свободный ввод, диктант.
- Условия и объяснения ru/kk/en, варианты ответа, правильная последовательность,
  пары и допустимые текстовые ответы. Диктант содержит HTTPS-аудио и атрибуцию.
- Добавление, удаление и перестановка заданий; от 1 до 30 заданий в тесте.
  В вариантах/парах минимум 2 и максимум 30 элементов, допустимых ответов 1–30.
- Предпросмотр заданий с ответами доступен только редактору/администратору.
- Содержание урока и тест сохраняются одной транзакцией с editVersion.
  Изменение вопросов, объяснений, ответов, типа или порога увеличивает revision
  теста и урока. Идентичное сохранение не увеличивает учебные версии.
- ID теста сохраняется, история попыток остаётся со снимками прежних заданий.
  Новые записи аудита включают тест до/после; старые записи не дополняются.
- При публикации повторно проверяются задания и правильные ответы. Ограничения
  идентификаторов и текстовых ответов согласованы с ученическим API.
- Удаление всего существующего теста не поддерживается: в нём должно оставаться
  хотя бы одно задание. Тип существующего задания меняется удалением и созданием
  нового; если оно единственное, сначала нужно добавить замену.

## API

- GET `/api/content/units` — доступные разделы с уровнем и программой.
- GET/POST `/api/content/lessons` — список/создание.
  Создание: `{unitId,slug,title,minutes}`; ответ `{id}`.
- GET/PATCH `/api/content/lessons/:id` — содержание/изменение черновика.
  PATCH: `{version,title,minutes,blocks?,quiz?}`; блок `{kind,content}`.
  Отсутствие blocks сохраняет содержание, пустой массив удаляет все блоки.
  quiz: `{kind,passPercent,questions}`; отсутствие сохраняет тест, null запрещён.
  GET возвращает редактору полный тест с правильными ответами.
- POST `/api/content/lessons/:id/state` — `{version,state}`.

Для всех методов проверяются сессия и права; для изменений также CSRF.
Старые опубликованные записи распознаются по published=true.
Существующим аккаунтам роли автоматически не назначались.

Запуск: Docker, `pnpm db:deploy`, `pnpm db:generate`, `pnpm server:build`,
`pnpm server:dev`, `pnpm dev`. На Windows остановить API перед db:generate.
Для этого этапа новая миграция не нужна. API запускается из dist-server:
после изменения backend нужно пересобрать и перезапустить процесс.
