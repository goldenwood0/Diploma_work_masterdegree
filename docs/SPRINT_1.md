# Спринт 1 — аккаунт и база данных

## Что реализовано

- NestJS API и PostgreSQL с Prisma и версионируемой миграцией accounts.
- Пользователь, настройки, роли STUDENT/EDITOR/ADMIN, сессии и одноразовые токены.
- Регистрация, подтверждение email, повторная отправка письма, вход, выход,
  выход со всех устройств, восстановление пароля.
- Формы React связаны с API; кабинет открывается после входа, профиль показывает
  настоящий аккаунт. Учебные показатели по-прежнему демонстрационные.
- Пароли хешируются scrypt с солью; токены хранятся только как SHA-256-хеши.
- Cookie HttpOnly, SameSite=Strict, Secure в production; срок сессии — 7 дней.
- Origin и специальный заголовок обязательны для POST; CORS не включён.
- Ссылки подтверждения действуют 24 часа, восстановления — 30 минут; сброс
  пароля отзывает все сессии. Потребление токенов выполняется транзакционно.
- Права определены по ролям; `/api/admin/users` доступен только с users:read.
- Лимиты: 60 запросов/IP и 10 запросов/email за 15 минут на auth-операциях.
- GitHub Actions проверяет типы, миграцию, API-тесты и сборку при push/PR.

## Локальный запуск

Нужны Node.js 22, pnpm и запущенный Docker Desktop.

1. `pnpm install --frozen-lockfile`
2. Скопировать `.env.example` в `.env`, заменить пароль в POSTGRES_PASSWORD
   и DATABASE_URL на одинаковое случайное значение. Не коммитить `.env`.
3. `docker compose up -d --wait`
4. `pnpm db:generate`
5. `pnpm db:deploy`
6. `pnpm server:build`
7. В первом терминале: `pnpm server:dev`
8. Во втором терминале: `pnpm dev` (если Vite ещё не запущен).

Приложение: http://127.0.0.1:8443. Использовать этот адрес, совпадающий с
APP_ORIGIN. API: порт 3001. PostgreSQL: порт 5433. Почта Mailpit:
http://127.0.0.1:8025. Все опубликованные порты Docker доступны только локально.
Vite перенаправляет `/api` на API. При изменении API_PORT изменить и proxy Vite.
После изменений сервера повторить сборку и перезапустить API.

Регистрация отправляет письмо в Mailpit; наружу письма в локальной конфигурации
не отправляются. Открыть ссылку из письма, подтвердить email и войти.
Готового общего аккаунта или публичного пароля администратора нет.

Остановка контейнеров: `docker compose stop`. Данные PostgreSQL сохраняются
в volume. Не удалять volume, если нужно сохранить аккаунты.

## API

| Метод и адрес | Назначение |
|---|---|
| GET /api/health | Проверка процесса API |
| POST /api/auth/register | email, name, password; роль нельзя передать |
| POST /api/auth/login | email, password; устанавливает cookie |
| GET /api/auth/me | Данные текущего аккаунта, без хеша пароля |
| POST /api/auth/logout | Завершить текущую сессию |
| POST /api/auth/logout-all | Завершить все сессии текущего пользователя |
| POST /api/auth/resend-verification | email |
| POST /api/auth/verify-email | token |
| POST /api/auth/forgot-password | email |
| POST /api/auth/reset-password | token, password |
| GET /api/admin/users | Первые 50 пользователей, только users:read |

POST использует JSON, `Origin: <APP_ORIGIN>` и `X-ZhPath-Request: 1`.
Регистрация и восстановление возвращают общее сообщение для существующего
и неизвестного адреса. При сбое SMTP возвращается ошибка; регистрацию можно
продолжить через повторную отправку подтверждения после восстановления почты.

## Проверки

`pnpm typecheck`, `pnpm server:build`, `pnpm test:server`, `pnpm build`.
Тесты используют подключённую БД, создают только уникальные адреса @example.test
и удаляют только созданных ими пользователей. На production тесты запрещены.
Почтовый транспорт заменяется тестовым сборщиком токенов в API-тестах.
Отдельно локально проверена настоящая SMTP-доставка в Mailpit и подтверждение
по токену из доставленного письма. Формы входа и регистрации осмотрены в браузере.

## Границы этапа

Перед публичным запуском нужны реальный SMTP, HTTPS и reverse proxy для `/api`.
API сейчас слушает 127.0.0.1. За доверенным proxy нужно явно настроить доверие
к адресу proxy для IP-лимитов; не доверять произвольному X-Forwarded-For.
Лимитер хранится в памяти одного процесса; общий Redis-лимитер нужен до
масштабирования на несколько экземпляров. Очистку истёкших токенов/сессий
и очередь повторной доставки писем добавить перед production.
Настройки обучения и локализация — спринт 2; админский интерфейс — спринт 6.

[Prisma migrations](https://www.prisma.io/docs/orm/v6/prisma-migrate/getting-started).
