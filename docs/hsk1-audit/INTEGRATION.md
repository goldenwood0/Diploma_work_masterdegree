## Проверенный перенос на копии — 24.10.2026

План ниже не применён к рабочим данным. Он проверен реальными маршрутами
приложения в новой схеме PostgreSQL: 10 multipart загрузок, 13 замен ссылок,
пять POST draft и PATCH содержания. Проверены 403/404 для ученика, 409 при
старой версии/повторном черновике, сохранение действующих материалов, попыток,
прогресса и SRS. Автоматической публикации в новом инструменте нет.

Воспроизведение из корня проекта (БД 5433 должна работать):

```powershell
npm run server:build
node --env-file=.env scripts/audit-hsk1.mjs --verify
node --env-file=.env scripts/plan-hsk1-integration.mjs --live
node --env-file=.env scripts/check-hsk1-transfer.mjs
```

Последний скрипт разрешает только локальную zhpath:5433/public как исходную БД,
создаёт уникальную hsk1_transfer_<uuid>, применяет миграции только к ней и
копирует только пять учебных материалов из проверенного снимка. Собственные
ученики/редактор создаются в этой схеме; вход, прохождение, загрузки и изменения
содержания выполняются реальными API. Рабочая public читается в READ ONLY.
После проверки схема удаляется, её отсутствие и контрольные суммы всех public-
таблиц сверяются. Итог — transfer-check.json; повторный прогон создаёт новую схему.
Не запускать два экземпляра одновременно: журналы имеют фиксированные имена.

Опциональный браузерный стенд: в отдельном терминале установить
`$env:HSK1_BROWSER='1'` и запустить тот же скрипт. После готовности API 3002
запустить `node scripts/preview-hsk1-isolated.mjs` (нужна свежая build).
Стенд 8446 использует только временную схему; собственные реквизиты лежат в
outputs/hsk1-browser-ready.json, их не публиковать. Не использовать рабочий аккаунт.
Для штатной очистки создать outputs/hsk1-browser-stop; дождаться Cleanup=true
и public unchanged=true, затем остановить только этот preview. Есть предел
ожидания 30 минут. Не прерывать runner принудительно: finally при kill не гарантирован.
Если процесс аварийно прерван, использовать точное имя собственной схемы из
журнала, проверить его принадлежность этому запуску и удалять только её;
не очищать схемы по маске и не затрагивать public.

[Доказательства, браузерные ограничения и очистка](REHEARSAL_2026-10-24.md).
Для реального переноса нужны человеческая приёмка и отдельное решение пользователя;

## Повторяемая проверка перед переносом

Из корня проекта после `npm run server:build`:

```powershell
node scripts/test-hsk1-audio.mjs
node --env-file=.env scripts/plan-hsk1-integration.mjs --live
```

Второй скрипт разрешает только локальную `5433/zhpath/public`, читает уроки
в READ ONLY транзакции и сверяет revision/editVersion, публикацию и отсутствие
чужого черновика. MATCH означает только совпадение версий, не приёмку содержания.
FAILED/CONFLICT блокируют перенос; скрипт возвращает ошибку и сохраняет причину
без реквизитов подключения. Без --live проверяются только файлы.
Никакой режим скрипта не пишет в БД и не выполняет HTTP-запросы на изменение.

## Последовательность редактора

1. Проверить окружение через `check-local-session.mjs`, затем повторить live-проверку.
   Убедиться, что это нужная локальная БД. Не переносить ID из другой базы.
2. Войти существующим EDITOR/ADMIN. Не менять роли других пользователей.
   Проверенные WAV загрузить через `/#/media`; multipart `POST /api/media`:
   файл плюс ровно name/author/license/sourceUrl/licenseUrl из uploads[].metadata.
   Сначала сверить имеющиеся записи, чтобы не создавать дубликаты при повторе.
3. Для каждого файла сохранить возвращённый audioUrl вида `/api/media/<id>/file`
   рядом с assetKey. Прослушать файл из медиатеки. Не использовать Windows-путь,
   выдуманный ID или URL другой записи. Сохранить CREDITS и сведения о конвертации.
4. Заменить все 13 путей lessons[].replacements в копиях draft по assetKey.
   Ссылки в двух диктантах тоже обязательны. Атрибуцию сохранить.
5. Непосредственно перед изменением GET `/api/content/lessons/:id`: сверить обе
   версии, published=true и hasDraft=false. При расхождении остановиться и
   сравнить изменения; не перезаписывать чужой черновик.
6. POST `/api/content/lessons/:id/draft` с `{version: актуальный editVersion}`.
   Ответ содержит новую editVersion. PATCH `/api/content/lessons/:id` с этой
   **возвращённой**, а не прежней версией, плюс title/minutes/blocks/quiz из draft.
   Использовать штатную сессию, Origin и X-ZhPath-Request. При 409 перечитать;
   автоматическое повторение устаревшего PATCH запрещено.
7. GET того же урока: проверить hasDraft=true, published=true, исходную учебную
   revision и полное совпадение сохранённого черновика с подготовленным объектом.
   Прослушать блоки и диктанты в редакторском предпросмотре. Ученик продолжает
   видеть прежнюю редакцию; новые локальные медиа из одних черновиков ученику недоступны.
8. После преподавателя/переводчиков/проверки прав отправить на REVIEW штатно.
   Публикация не входит в этот план: отдельное решение после показа изменений.

Если перенос прервался, перечитать медиатеку и уроки и восстановить фактический
этап; не удалять записи и не повторять все загрузки вслепую. Публикация изменит
учебную revision и потребует нового прохождения. Чтобы не менять зачёт текущих
учеников, новую редакцию показывать в отдельной копии окружения.
